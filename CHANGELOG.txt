ROOT CAUSE FOUND
ZIP 50 introduced a second heavy background worker for completed-history
maintenance while the full Scanner v2 analysis could run at the same time.

At the same time, _history_rollover_state() was loading the ENTIRE 220+ session
history parquet on Streamlit reruns simply to determine whether the history date
was stale.

That combination can create several large copies of the multi-million-row
history in memory at once:
- Streamlit UI/history freshness check
- Scanner v2 analysis
- EOD history reconciliation/compaction
- pandas concat copies
- whole compact parquet bytes during cloud upload

The app working first and then eventually dropping to Streamlit's white
"Oh no. Error running app" page is consistent with the worker being killed
under memory/resource pressure rather than a Python syntax error.

FIXES
1. EOD freshness checks now use the tiny scanner_manifest.json only.
   They no longer read the full historical parquet on every rerun.

2. Heavy Scanner v2 analysis and heavy EOD history maintenance are serialized
   with one process lock so they cannot double-load the full market history.

3. The 20-second CURRENT PRICE overlay remains independent and keeps running.
   Current displayed prices do not have to wait for EOD maintenance.

4. Each new completed day is still saved immediately as:
   - local day shard
   - cloud/Supabase day shard
   - local compact history
   - manifest / completed_dates / last_saved_session

5. The full compact history parquet is no longer uploaded after EVERY missing
   day. It is uploaded once after catch-up finishes. This avoids repeatedly
   creating a huge in-memory bytes copy.

6. No Scanner scoring, ranking, metadata, Float, Market Cap, Shares Outstanding,
   Watchlist, Live Chart, or current-price logic was changed.

IMPORTANT
Do NOT reset Scanner history.

No SQL changes.
