CHANGELOG

1. COMPLETED-DAY HISTORY CATCH-UP
- Detects whether durable history is actually behind the latest completed U.S. session.
- Uses New York market time and a 4:15 PM ET completion buffer.
- Uses Alpaca's market calendar when available, so weekends/market holidays are not treated as missing sessions.
- Fetches every missing completed market day from Massive in chronological order.

2. PERSIST EACH DAY IMMEDIATELY
Every successful missing session is now persisted before the updater moves on:
- individual local day shard
- Supabase day shard upload attempt
- compact local history parquet
- compact Supabase history upload attempt
- scanner manifest
- completed_dates
- last_saved_session

A cloud upload problem no longer throws away a successfully downloaded local EOD session.

3. RESTART RECOVERY
- If a prior process saved a day shard but stopped before rebuilding compact history, the next run reconciles that shard automatically.
- The historical database can therefore recover from partial Streamlit sleeps/redeploys.

4. AUTOMATIC UPDATE
- Scanner page automatically starts catch-up only when history is actually behind.
- Once history reaches the latest completed session, it stops launching unnecessary maintenance workers.
- If new EOD history is added, the saved heavy scan is marked stale so the next normal scanner poll recalculates against the updated technical history.

5. VISIBLE DIAGNOSTICS
Scanner v2 Market Database now shows:
- current saved historical date
- target completed date
- session currently being fetched
- progress
- exact last provider/persistence error if catch-up fails

This removes the previous silent-failure problem where the UI could stay on an old date with no explanation.
